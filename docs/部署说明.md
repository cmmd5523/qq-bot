# 部署说明

项目代码可运行在 Linux 或 Windows；QQ 客户端及 NapCat 需要独立安装。参见 [NapCat 官方安装说明](https://napneko.github.io/guide/boot/Shell)。Docker 环境建议至少4GB内存；2GB机器应限制并发并实测内存。

## Linux Docker

构建本仓库镜像并通过 Compose 运行。先按 README 创建本地配置，再创建仅存在本机的 compose.yaml。不要把真实 Token 写入公开文件。

```yaml
services:
  bot:
    build: .
    restart: unless-stopped
    network_mode: host
    volumes:
      - .:/opt/qq-bot
      - ./qq:/app/.config/QQ
      - ./napcat/cache:/app/napcat/cache
  napcat:
    image: mlikiowa/napcat-docker:latest
    restart: unless-stopped
    network_mode: host
    environment:
      MODE: reverse_ws
      ONEBOT_URL: ws://127.0.0.1:5700/onebot/v11/ws
      WEBUI_TOKEN: ${NAPCAT_WEBUI_TOKEN:?Set a private random token}
    volumes:
      - ./qq:/app/.config/QQ
      - ./napcat/config:/app/napcat/config
      - ./napcat/cache:/app/napcat/cache
      - .:/opt/qq-bot
```

将 NapCat WebUI 的 host 设为127.0.0.1后，通过SSH转发6099访问。首次启动未配置 host 时，应先在隔离网络中完成设置；不能直接把管理面板暴露到公网。不要将整个/app/napcat目录用空目录覆盖。登录二维码与会话均属私人数据。

```sh
docker compose up -d --build
docker compose logs --tail=100 bot napcat
```

登录后验证QQ文字收发、语音收发、Telegram长轮询和可选插件。仅端口监听不代表完整消息链路通过。

某些嵌套LXD环境的Docker AppArmor策略可能限制Chromium/QQ。需先定位具体拒绝原因，再仅对受影响容器调整策略，不建议全局关闭安全策略。镜像发布标签应在自行验证后固定digest。

Whisper语音模型可通过huggingface_hub下载Systran/faster-whisper-small至runtime/whisper-small；模型较大，下载后单独验收加载与转写。
